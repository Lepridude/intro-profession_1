## Моя рефлексия

В этой работе я разобрал связку GitHub, VS Code и Python на примере программы, которая получает данные о фильме через OMDb API. Лучше всего получилось отправить первый запрос и увидеть JSON-ответ о фильме, а сложнее всего было настроить SSH-ключ и разобраться, как поменять адрес репозитория командой `git remote set-url`. Работа в `master` отличается от работы в отдельной ветке тем, что в основной ветке хранится стабильная версия проекта, а в отдельной ветке можно подготовить изменение и проверить его перед слиянием. Commit фиксирует состояние проекта в истории, поэтому при необходимости можно вернуться к предыдущей версии. Виртуальное окружение `.venv` нужно, чтобы библиотеки устанавливались отдельно для этого проекта и не мешали другим. Файл `.env` используют для хранения секретов: API-ключ не стоит записывать прямо в код, особенно если репозиторий публичный. Файл `.env` добавлен в `.gitignore`, поэтому он не должен попадать в коммиты. JSON — текстовый формат хранения данных; после получения ответа программа разбирает его и обращается к нужным полям, например `Title`, `Year`, `Genre` и `Director`. Панель управления версиями в VS Code помогает видеть изменённые файлы, создавать commit и отправлять изменения в удалённый репозиторий. В улучшенной версии добавлена проверка поля `Response`, чтобы корректно обработать ситуацию, когда фильм не найден. Для проверки нужно использовать существующее название фильма, несуществующее название и неверный API-ключ. Если бы я выполнял работу ещё раз, то добавил бы `.gitignore` до первого commit и проверял бы содержимое ноутбука перед отправкой, чтобы случайно не опубликовать ключ.
